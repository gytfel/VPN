# VPN на Remnawave — сборка от нуля

Здесь всё, что нужно, чтобы поднять свой VPN-сервис: панель, ноду, страницу
подписки, лимит устройств, Telegram-бота с оплатой и работу по белым спискам.

> **Ставите первый раз?** Идите по [SETUP.md](SETUP.md) — там пошагово, с
> точными командами, готовым конфигом Reality и проверкой после каждого шага.
> Этот файл — обзор архитектуры и справочник.

## Что из чего состоит

Два сервера. Это не прихоть: через панель трафик пользователей не идёт, ей
хватает дешёвой VPS, а нода наоборот должна стоять там, где хороший канал.

```
                    ┌─────────────────────────────┐
   вы ───admin──────▶  СЕРВЕР ПАНЕЛИ              │
                    │  panel.example.com  (закрыт)│
                    │  sub.example.com    (открыт)│
                    │                             │
                    │  Caddy ─┬─ панель :3000     │
                    │         ├─ подписка :3010   │
                    │         └─ бот :8080        │
                    └──────────────┬──────────────┘
                                   │ :2222, только с IP панели
                    ┌──────────────▼──────────────┐
 клиент ───VLESS────▶  СЕРВЕР НОДЫ                │
                    │  Xray, порт 443             │
                    └─────────────────────────────┘
```

Клиент ходит за конфигом на `sub.example.com`, а трафик гоняет через ноду.
Панель наружу для клиентов не нужна вообще.

## Порядок

Порядок именно такой. Ноду нельзя создать раньше Config Profile — панель
требует указать профиль и инбаунды прямо в момент создания ноды.

| # | Что | Где делается | Чем |
|---|---|---|---|
| 1 | Сервер панели | сервер панели | `install-panel.sh` |
| 2 | Config Profile: VLESS Reality | панель, браузер | руками |
| 3 | Сервер ноды + нода в панели | сервер ноды | руками |
| 4 | Host — как клиент видит ноду | панель, браузер | руками |
| 5 | Internal Squad — тариф | панель, браузер | руками |
| 6 | Страница подписки на `sub` | сервер панели | руками |
| 7 | Лимит устройств HWID | сервер панели | `enable-hwid.sh` |
| 8 | Telegram-бот с оплатой | сервер панели | `bot/` |
| 9 | Белые списки | где угодно | `whitelist/build-whitelist.sh` |
| 10 | Бэкапы | сервер панели | `backup.sh` |

Шаги 2–6 делаются в панели руками — их не автоматизировать разумным образом,
там нужны ваши домены, ключи и решения. Всё остальное — скрипты из этого
репозитория.

## 1. Сервер панели

Нужны два поддомена, оба A-записью на IP сервера панели, **с серым значком
Cloudflare** на время установки:

| Поддомен | Зачем | Доступ |
|---|---|---|
| `panel.example.com` | админка | закрыта по IP |
| `sub.example.com` | подписки, бот | публичный |

```bash
chmod +x install-panel.sh
sudo ./install-panel.sh
```

Скрипт спросит домены и ваш IP, дальше сам поставит фаервол, Docker, панель,
Caddy и в конце проверит, что всё поднялось.

**Сразу после установки откройте `https://panel.example.com` и
зарегистрируйтесь.** Первый зарегистрировавшийся становится super-admin —
пока вы этого не сделали, им может стать кто угодно, кто найдёт домен.

Подробности, грабли и что делать, если заперлись снаружи — в
[README (1).md](README%20%281%29.md).

## 2. Config Profile — VLESS Reality

Панель → **Config Profiles** → создать.

Профиль — это конфиг Xray, который поедет на ноды. Минимум, который работает:
один инбаунд VLESS с Reality на порту 443.

Что понадобится:

- **Ключи Reality.** Панель умеет генерировать их сама в редакторе профиля.
  Если делаете руками: `docker exec remnanode xray x25519`.
- **Маскировочный домен (SNI).** Чужой сайт, за который выдаёт себя нода:
  быстрый, с TLS 1.3 и HTTP/2, не заблокированный в вашей стране и не
  Cloudflare. Годятся, например, крупные CDN вроде `cdn.jsdelivr.net`.
- **Short ID** — короткая hex-строка, панель тоже сгенерирует.

Профиль сохранится с инбаундом внутри. Его UUID понадобится на следующем шаге —
точнее, панель подставит его сама, когда будете создавать ноду.

## 3. Сервер ноды

Отдельная VPS. Здесь важен канал и локация, а не ядра.

**Фаервол.** Порт ноды `2222` открывается **только для IP панели** — иначе
в служебное API ноды сможет постучаться кто угодно:

```bash
ufw default deny incoming
ufw allow 22/tcp
ufw allow 443/tcp
ufw allow from IP_ПАНЕЛИ to any port 2222 proto tcp
ufw --force enable
```

**Установка.** Панель → **Nodes** → создать. Заполняете имя, адрес (IP ноды),
страну и выбираете Config Profile из шага 2 вместе с его инбаундами. После
создания панель показывает готовый `docker-compose.yml` для ноды — с уже
подставленным `SECRET_KEY`. Скопируйте его на сервер ноды:

```bash
mkdir -p /opt/remnanode && cd /opt/remnanode
nano docker-compose.yml     # вставить то, что показала панель
docker compose up -d
```

Нода поднимается в `network_mode: host` — так Xray слушает 443 напрямую.

Через минуту в панели нода должна загореться зелёным. Не загорелась — почти
всегда фаервол: проверьте, что 2222 открыт именно для IP панели.

## 4. Host — как клиент видит ноду

Панель → **Hosts** → создать.

Нода — это сервер, Host — это то, что окажется в конфиге у клиента: адрес,
порт, SNI, привязка к инбаунду. Один инбаунд может отдаваться несколькими
хостами (разные домены на одну ноду).

Здесь же задаётся название, которое пользователь увидит в списке серверов.

## 5. Internal Squad — это ваш тариф

Панель → **Internal Squads** → создать.

Сквад — набор инбаундов, к которым пользователь получает доступ. Хотите
тариф «одна страна» и тариф «все страны» — это два сквада.

**Запишите UUID сквада**, он понадобится боту в `REMNAWAVE_SQUAD_UUID`.
Без сквада пользователь создастся, но доступа к нодам у него не будет.

На этом VPN уже работает: создайте в панели тестового пользователя, возьмите
у него ссылку подписки и подключитесь.

## 6. Страница подписки на `sub`

Пока её нет, клиенты получают конфиг только по прямой ссылке. Страница даёт
человеческий вид с кнопками «установить приложение» под каждую платформу.

```bash
mkdir -p /opt/remnawave/subscription-page && cd /opt/remnawave/subscription-page
```

`.env`:

```
APP_PORT=3010
REMNAWAVE_PANEL_URL=http://remnawave:3000
REMNAWAVE_API_TOKEN=      # панель → API Tokens
TRUST_PROXY=1
```

`docker-compose.yml`:

```yaml
services:
  remnawave-subscription-page:
    image: remnawave/subscription-page:latest
    container_name: remnawave-subscription-page
    hostname: remnawave-subscription-page
    restart: always
    env_file: .env
    networks:
      - remnawave-network

networks:
  remnawave-network:
    name: remnawave-network
    external: true
```

`TRUST_PROXY=1` обязателен: страница стоит за Caddy, и без него в логах и
правилах будет IP контейнера вместо IP клиента.

Порт наружу не публикуем — до неё ходит только Caddy по внутренней сети.

## 7. Лимит устройств HWID

Чтобы одну подписку не расшаривали на весь подъезд:

```bash
chmod +x enable-hwid.sh
./enable-hwid.sh --limit 3
```

Посмотреть: `--status`, откатить: `--off`.

| Что | Значение |
|---|---|
| `hwidDeviceLimit` у пользователя | главнее общего лимита |
| `hwidDeviceLimit = 0` | безлимит для этого пользователя, **не запрет** |
| не задан | берётся общий `--limit` |

**Грабля.** После включения клиенты, которые не умеют HWID, перестают
получать подписку вообще — панель отвечает отказом. Happ, v2rayNG и
Streisand HWID шлют. Проверьте на одном живом пользователе, прежде чем
включать для всех.

## 8. Telegram-бот с оплатой

Бот продаёт доступ через CryptoBot, заводит покупателя в панели и выдаёт
одноразовую ссылку на настройку выбранного устройства — iPhone, Android,
Windows или Mac.

Новым пользователям первой кнопкой предлагается **3 дня бесплатно** — по
кнопке «Получить», не автоматически. Один раз на человека, настраивается
через `TRIAL_DAYS` и `TRIAL_ENABLED`.

```bash
cp -r bot /opt/remnawave/bot && cd /opt/remnawave/bot
cp .env.example .env
nano .env          # токены бота, панели, CryptoBot, UUID сквада из шага 5
nano tariffs.json  # цены и сроки
docker compose up -d --build
```

Установка целиком, настройка вебхука и грабли — в [bot/README.md](bot/README.md).

## 9. Caddy — собираем `sub` воедино

К этому моменту на домене подписки должны жить три вещи: страница подписки,
одноразовые ссылки бота и вебхук оплаты. Допишите в
`/opt/remnawave/caddy/Caddyfile`:

```caddyfile
https://sub.example.com {
    encode

    handle /get/* {
        reverse_proxy http://vpn-bot:8080
    }

    handle /cryptobot/webhook {
        reverse_proxy http://vpn-bot:8080
    }

    handle {
        reverse_proxy http://remnawave-subscription-page:3010
    }
}
```

Блок `https://panel.example.com` с фильтром по IP и блок `:443` с маскировкой
не трогайте — они уже там от шага 1.

```bash
cd /opt/remnawave/caddy
docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile
```

Теперь на `sub` можно включать оранжевый значок Cloudflare — фильтра по IP
там нет. На `panel` оставьте серый.

## 10. Белые списки

Чтобы через туннель шли только нужные сайты, а остальное — напрямую:

```bash
cd whitelist && ./build-whitelist.sh
```

Готовые шаблоны из `whitelist/out/` вставляются в панель → **Templates** →
**Subscription Templates**. Подробности — в
[whitelist/README.md](whitelist/README.md).

## 11. Бэкапы

Настройте сразу, пока база пустая и не жалко ошибиться:

```bash
cp backup.sh /opt/remnawave/backup.sh
chmod +x /opt/remnawave/backup.sh
nano /opt/remnawave/backup.sh    # вписать TG_TOKEN и TG_CHAT
crontab -e
```

```
0 4 * * * /opt/remnawave/backup.sh >> /var/log/rw-backup.log 2>&1
```

Запустите руками и убедитесь, что дамп дошёл в Telegram. И **заберите с
сервера `/opt/remnawave/backups/env.backup`** — без `.env` дамп базы
бесполезен, а в Telegram он намеренно не отправляется.

## Проверка, что всё включено

```bash
# панель жива
curl -s -o /dev/null -w '%{http_code}\n' https://panel.example.com     # 200 или 204

# маскировка: голый IP отдаёт пустоту
curl -sk -o /dev/null -w '%{http_code}\n' https://IP_ПАНЕЛИ            # 204

# страница подписки отвечает
curl -s -o /dev/null -w '%{http_code}\n' https://sub.example.com       # 200

# бот жив
curl -s https://sub.example.com/healthz                                # {"ok": true}

# лимит устройств
./enable-hwid.sh --status                                              # ВКЛЮЧЕН

# контейнеры
docker ps --format '{{.Names}}\t{{.Status}}'
```

Дальше по-живому: купите доступ через бота с другого Telegram-аккаунта,
выберите устройство, откройте одноразовую ссылку на телефоне и подключитесь.
Затем откройте её ещё раз — должна отдать отказ.

Если включали белые списки: `ipinfo.io` покажет IP ноды, а `2ip.ru` — ваш
домашний IP.

## Шпаргалка

```bash
# логи
cd /opt/remnawave        && docker compose logs -f   # панель
cd /opt/remnawave/caddy  && docker compose logs -f   # Caddy
cd /opt/remnawave/bot    && docker compose logs -f   # бот
cd /opt/remnanode        && docker compose logs -f   # нода (на её сервере)

# заперлись в админке
docker exec -it remnawave remnawave                  # rescue CLI, домен не нужен

# обновить панель
cd /opt/remnawave && docker compose pull && docker compose up -d
```
