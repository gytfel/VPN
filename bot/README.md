# Шаг 7 — Telegram-бот с оплатой и одноразовыми ссылками

Бот продаёт доступ через CryptoBot, заводит покупателя в панели и выдаёт
**одноразовую ссылку** на настройку выбранного устройства: iPhone, Android,
Windows или Mac.

## Как это выглядит для покупателя

1. `/start` → выбирает тариф
2. Платит счёт в CryptoBot
3. Бот заводит подписку в панели и спрашивает: **какое устройство настраиваем?**
4. Покупатель жмёт «🍏 iPhone / iPad» (или Android / Windows / macOS)
5. Приходит ссылка. Открыл на нужном устройстве — открылась страница с кнопкой
   «Добавить подписку», приложение подхватило конфиг
6. Ссылка сгорела. Нужно второе устройство — вернулся в бота и взял новую

Ссылка одноразовая по-настоящему: первый показ страницы гасит токен в базе.
Второй заход получает 410 и объяснение. Есть и срок жизни — по умолчанию
30 минут.

## Что нужно до установки

**API-токен панели.** Панель → API Tokens → создать. Ему нужны права на чтение
и создание пользователей.

**Internal Squad.** UUID сквада, в который попадают покупатели (шаг 4).
Без него пользователь создастся без доступа к нодам.

**Токен CryptoBot.** [@CryptoBot](https://t.me/CryptoBot) → Crypto Pay →
Create App → токен.

**Токен бота.** [@BotFather](https://t.me/BotFather) → `/newbot`.

## Установка

Бот ставится на тот же сервер, что и панель — он ходит в неё по внутренней
docker-сети, наружу API панели не открывается.

```bash
cp -r bot /opt/remnawave/bot
cd /opt/remnawave/bot
cp .env.example .env
nano .env          # заполнить токены
nano tariffs.json  # свои цены и сроки
docker compose up -d --build
```

### Caddy

Одноразовые ссылки и вебхук оплаты живут на домене подписки. Допишите в
`/opt/remnawave/caddy/Caddyfile`:

```caddyfile
https://sub.example.com {
    encode

    # одноразовые ссылки на подключение
    handle /get/* {
        reverse_proxy http://vpn-bot:8080
    }

    # уведомления об оплате от CryptoBot
    handle /cryptobot/webhook {
        reverse_proxy http://vpn-bot:8080
    }

    # всё остальное — страница подписки из шага 5
    handle {
        reverse_proxy http://remnawave-subscription-page:3010
    }
}
```

И перечитайте конфиг:

```bash
cd /opt/remnawave/caddy && docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile
```

### Вебхук CryptoBot

В @CryptoBot → Crypto Pay → ваше приложение → Webhooks укажите:

```
https://sub.example.com/cryptobot/webhook
```

Подпись вебхука проверяется, чужие запросы отбрасываются. Если вебхук почему-то
не дошёл, у покупателя есть кнопка «Я оплатил — проверить»: бот сам спросит
статус счёта у CryptoBot. Двойного начисления при этом не будет — счёт
помечается применённым атомарно.

## Тарифы

`tariffs.json` монтируется в контейнер, пересборка для правки не нужна —
достаточно `docker compose restart`.

```json
{"id": "m3", "title": "3 месяца", "days": 90, "devices": 2, "price": "4", "asset": "USDT", "traffic_gb": 0}
```

| Поле | Смысл |
|---|---|
| `days` | на сколько дней продлевается доступ |
| `devices` | лимит устройств (`hwidDeviceLimit` в панели) |
| `price` / `asset` | цена и валюта CryptoBot (`USDT`, `TON`, `BTC`…) |
| `traffic_gb` | лимит трафика в месяц, `0` — безлимит |

Продление считается по-человечески: если подписка ещё жива, дни добавляются
к её концу, а не к сегодняшнему дню.

## Проверка

```bash
cd bot
python -m tests.smoke
```

Тесты гоняют логику без Telegram и без сети: одноразовость ссылки (включая
гонку двух одновременных заходов), deep-link'и всех четырёх платформ, проверку
подписи вебхука, защиту от двойного начисления и payload'ы к API панели против
поддельного сервера.

Живая проверка после установки:

```bash
docker compose logs -f vpn-bot
curl -s https://sub.example.com/healthz     # {"ok": true}
```

## Приложения

Deep-link'и взяты из конфига страницы подписки самой панели, не выдуманы.

| Платформа | Основное | Запасное |
|---|---|---|
| iPhone / iPad | Happ | Streisand |
| Android | Happ | v2rayNG |
| Windows | Happ | Koala Clash |
| macOS | Happ | Koala Clash |

Если поменяете набор приложений в панели, поправьте `app/devices.py`.

## Грабли

### Телеграм сжигает ссылку превью

Телеграм сам открывает ссылки, чтобы нарисовать превью — одноразовая ссылка
сгорела бы до того, как её увидит человек. Поэтому превью в сообщениях
выключено, а на стороне сервера запросы от превью-ботов узнаются по
User-Agent и токен не гасят.

### «Ссылка одноразовая» — это не привязка к железу

Одноразовость означает, что ссылку нельзя переслать другу и использовать
второй раз. Само число устройств ограничивает панель через
`hwidDeviceLimit`: клиент сообщает свой HWID при подключении, и лишние
устройства панель не пускает. Включите HWID Device Limit в настройках
панели (шаг 6), иначе лимит устройств останется декоративным.

### Пользователь оплатил, а панель не ответила

Бот честно скажет об этом покупателю и попросит написать в поддержку.
Счёт при этом уже помечен применённым, так что после ручной выдачи доступа
повторного начисления не случится. Ищите такие случаи в логах по строке
`Не смог создать пользователя в панели`.

### Бот не видит панель

Проверьте, что контейнер в той же сети:

```bash
docker exec vpn-bot python -c "import socket; print(socket.gethostbyname('remnawave'))"
```

Сеть `remnawave-network` должна быть уже создана панелью — бот подключается
к ней как external.
