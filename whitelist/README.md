# Белые списки — VPN только для нужных сайтов

По умолчанию через туннель идёт весь трафик. Белый список переворачивает логику:
**через VPN идут только домены из списка, всё остальное — напрямую.**

Зачем:

- быстрее: банки, госуслуги, локальные сервисы и торренты не гоняются через ноду
- дешевле: трафика через сервер в разы меньше
- незаметнее: провайдер видит обычный домашний трафик, а не «всё в одну точку»
- ничего не ломается: сайты с гео-блокировкой по IP (банк-клиент, Госуслуги) работают как обычно

## Как это устроено

Маршрутизация живёт **в конфиге клиента**, а не на сервере. Панель отдаёт клиенту
конфиг по шаблону — мы подменяем шаблон так, чтобы в нём были правила «эти домены в
туннель, остальное напрямую».

```
domains.txt  →  build-whitelist.sh  →  4 шаблона  →  вставить в панель  →  клиент
```

Важно понимать: сервер тут ни при чём. Нода по-прежнему готова пропустить что угодно —
просто клиент ей больше ничего лишнего не шлёт.

## Сборка

```bash
cd whitelist
chmod +x build-whitelist.sh
./build-whitelist.sh
```

В `out/` появятся четыре файла. Готовые лежат в репозитории — если список вас
устраивает, собирать заново не нужно.

Опции:

| Опция | Что делает |
|---|---|
| `-a, --add FILE` | подмешать свой файл со списком доменов |
| `-u, --url URL` | подмешать список по ссылке |
| `-o, --out DIR` | куда сложить результат |
| `-g, --group NAME` | имя прокси-группы, если меняли его в панели |
| `--dns URL` | свой DoH-резолвер вместо `https://1.1.1.1/dns-query` |
| `--singbox-legacy` | формат sing-box до 1.12 (см. ниже) |

## Установка в панель

Панель → **Templates** → **Subscription Templates**. Для каждого типа вставьте
содержимое своего файла и сохраните:

| Тип шаблона | Файл |
|---|---|
| `XRAY_JSON` | `out/xray-json.json` |
| `SINGBOX` | `out/singbox.json` |
| `MIHOMO` | `out/mihomo.yaml` |
| `CLASH` | `out/clash.yaml` |

После сохранения в клиенте нажмите **обновить подписку**. Просто переподключиться
недостаточно — клиент возьмёт старый конфиг из кеша.

### Про XRAY_BASE64

Пятый тип шаблона, `XRAY_BASE64`, — это просто список ссылок `vless://`. Правил
маршрутизации в ссылке нет и быть не может, поэтому **клиенты на голых ссылках всегда
получат полный туннель**. Если белый список нужен всем без исключения — раздавайте
подписку так, чтобы клиент забирал `json`, `singbox`, `mihomo` или `clash`.

## Проверка, что заработало

Подключитесь и откройте:

1. `https://ipinfo.io` — домен в белом списке, должен показать **IP ноды**
2. `https://2ip.ru` — домена в списке нет, должен показать **ваш домашний IP**

Оба IP одинаковые? Клиент взял старый конфиг — обновите подписку принудительно
или удалите и добавьте профиль заново.

## Как менять список

Правьте `domains.txt` — по домену второго уровня на строку, поддомены подхватываются
сами. Потом пересоберите и перезалейте шаблоны:

```bash
./build-whitelist.sh
```

Свои домены удобно держать отдельным файлом, чтобы не конфликтовать при обновлении:

```bash
./build-whitelist.sh --add my-domains.txt
```

## Два режима одновременно

Если часть пользователей должна сидеть на полном туннеле, а часть — на белом списке,
одного набора шаблонов мало: шаблон применяется ко всем.

Remnawave умеет отдавать **разные шаблоны разным подпискам**. В панели заведите
второй именованный набор шаблонов (например `whitelist`) и переключайте на него через
**Subscription Response Rules** — в правиле указывается, какой шаблон отдать. Дефолтный
набор при этом остаётся полным туннелем.

## Грабли

### DNS

Если резолвить домены из белого списка через провайдерский DNS, часть заблокированных
сайтов не откроется даже через туннель — придёт подменённый ответ. Поэтому в шаблонах
запросы для доменов из списка уходят на DoH `1.1.1.1` **через туннель**, а всё
остальное резолвится системным резолвером как обычно.

Свой резолвер: `./build-whitelist.sh --dns https://8.8.8.8/dns-query`. Берите адрес
с IP, а не с именем — иначе резолвер придётся резолвить, и получится курица с яйцом
(скрипт это отработает, но лишний шаг).

### Версии sing-box

В sing-box 1.12 поменялся формат DNS-секции, в 1.14 старый убирают совсем. Поэтому:

- по умолчанию генерируется формат **1.12+** — официальное приложение sing-box, Karing,
  свежие сборки
- `--singbox-legacy` даёт формат для **1.10–1.11** — старые сборки Hiddify и подобные

Один файл под обе ветки сделать нельзя, форматы несовместимы. Если у пользователей
разнобой — держите два именованных шаблона (см. «Два режима одновременно»).

Проверено на Xray-core 26.3.27, sing-box 1.13.18 и 1.11.15, mihomo 1.19.29.

### Сайт из списка не открывается

Скорее всего домен отдаёт контент с другого домена, которого в списке нет. Откройте
консоль браузера (F12 → Network) и посмотрите, куда уходят упавшие запросы — добавьте
эти домены в список.

### Приложение ходит по IP, а не по имени

Правила работают по доменам. Если клиент подключается сразу к IP-адресу (некоторые
игры, торренты, свои сервисы), правило не сработает и трафик уйдёт напрямую. Это
осознанный компромисс: гонять весь IP-трафик в туннель — уже не белый список.
